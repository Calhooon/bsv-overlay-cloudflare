## Hosted boundary

The spike measured an accepted Promise callback committing its prefix (1 row),
then its continuation outside the transaction (2 rows). The explicit one-poll
model rolled back to 0. This PR must enforce that guard in Rust. A lost answer
is ambiguous: before the unit or after commit; replay resolves it using durable
keys. The later materializer has caps of 100 total statements and 4,000,000 bind
bytes, reserving cursor slots. These are not limits on an admission unit.

## Split and log implementation

`Engine::walk(&TaggedBEEF, SubmitMode, WalkBreachPolicy, &dyn EvidenceSource)
-> Result<Walked, WalkAnswer>` shares the existing bounded walk and broadcast
helpers. `Engine::admit(&Walked, &dyn LogTxn) -> Result<Admitted, AdmitRefusal>`
judges and mutates inside the open unit. The ordinary submit continues through
its existing fault handling; the log path has no undo or hold operation.

`AdmitEvidence.tx` maps txid to `TxEvidence { walk, network, proof }`.
Network verdicts are accepted (ARC or broadcaster name/time/status), refused,
or unavailable. Proof verdicts carry height/root or a refusal. `sidecars` maps
content hash to stored key or failed-put reason. Refusal notes are per-unit
scope state and return in both admitted and refused answers. No thread-local
carries either broadcaster verdicts or refusal notes.

`TopicAdmittanceContext` gains only `admission_seq: Option<u64>` and stays Copy.
The host builds managers and services over the log scope and evidence readers.
The generic CurrentTx log walk uses a read-only executor for its dry judgement
before broadcast. Ordinary submit does not call that executor.

`MemoryStorage::transaction` snapshots all persistent engine tables, manager
rows, unit records and outbox rows, polls once with a no-op waker, drops the
future before rollback, and checks the sticky statement failure. A rollback
RAII guard also handles native unwinding. `Pending` returns `admit_awaited_io`
with the active manager/service hook, never a committed prefix. The memory
model is a synchronous single-writer executor; a simultaneous/reentrant writer
gets `admission_busy` rather than exposing uncommitted rows through another unit.

`MemoryStorage::admit` resolves the log's predecessor request with an independent
unit and then retries the successor judgement. The extra carried-body pin proves
that a predecessor remains committed after a successor's deterministic refusal.
The anticipated bodies and network evidence come from the walk, not a network
call inside that unit. The existing 256-read bound is retained for anticipation.

Fault seams count engine, manager and outbox writes. The strengthened test 3
faults every write of a clean two-topic admission, compares all stored bytes,
and replays to the exact clean state. Test 11 now targets the applied insert
(after the output and service index statements). Additional pins cover a
swallowed failed statement, before-unit and after-commit lost answers, evidence
serialization, missing evidence, refusal note isolation, and dry-write attempts.
The outbox pin checks the exact envelope, retained attempt count on failed send,
one successful drain and an empty second drain.

## Boundary review

The generic CurrentTx log walk now carries its own successful ARC broadcast as
`NetworkVerdict::Accepted` only when the returned txid matches the subject.
Its dry judgement gates broadcasting; the ordinary submit's broadcast behavior
is preserved. A native broadcaster spy proves exactly one call during walk and
zero during admit.

Predecessor questions run with a nested read-only scope and the current unit
sequence. Their legacy naming helper records errors into the statement guard
instead of silently committing its fallback on the log path. Ordinary submit
passes no log and keeps its prior behavior. Proven carried predecessors are
included in anticipation/evidence even though their ancestors need no walk.
The carried-body stack holds only keys between attempts. There are 18 focused
native tests after this review. Lookup hooks use sorted service names, so two
refusing services give a stable word across HashMap seeds. A swallowed storage
fault takes precedence over a later deterministic verdict derived from that
incomplete store; the refusal remains transient.
