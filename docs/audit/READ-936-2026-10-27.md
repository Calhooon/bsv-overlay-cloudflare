## 4. The fix (this lane)

The invariant broken: an admitted pot the index holds leaves only by an eviction record or a readmission. Here it
left by a write the request owned, cut by the client's cancel, and then a correct successor made the cut permanent
(rule 6: a self-healing failure traded for a permanent one).

The arm: the gated engine write. Since this lane it is OWNED by `ctx.wait_until` from its first statement
(`crates/overlay-cloudflare/src/owned_write.rs owned_write`), and the request waits only on a `Handle` for its
output, raced against #838's deadline as before. If the request is dropped while the write runs, the write goes
on whole in its own task, the submission is put at rest at that moment as the deferred job
(`ef_deferred::defer_request_gone`, the same job and delay as #838's past-deadline deferral: the cover of a task
the platform itself cuts), and the task runs what the request would have run after its write
(`finish_past_deadline` under the cause `AfterAnswer::RequestGone`: the walk count, the landed predecessors' guard,
the write-side guard, the S2 decision, the notes), counted `submit_write_outlived_request_total`. #838's
past-deadline path is unchanged (`AfterAnswer::PastDeadline`).

The pins, RED then GREEN:
- `fix936::fix936_a_the_gated_write_is_owned_by_wait_until_never_by_the_request` and
  `fix936::fix936_b_a_gone_request_has_its_after_write_and_its_deferred_job` (the route's wiring, read from its
  source: the route runs on wasm only, as `fix838_fold`'s pins): RED on eaaee0ec by their own assertions
  ("the gated write is created owned, outside the request's future"; "the cover is the deferred job"), GREEN on
  the fix.
- `owned_write::tests::fix936_c` (the class, as eaaee0ec ran it: a request that owns a two-statement write and is
  dropped after the first never runs the second), `fix936_d` (the fix: the handle dropped after the first statement,
  the task runs the second, starts the cover once at the drop, and hands the output to the orphan path),
  `fix936_e` (a waiting request takes the output; no cover, no orphan), `fix936_f` (an output handed over and never
  taken runs the orphan path).
- `ef_deferred::fix838::fix838_the_gated_arm_races_its_write_and_hands_it_on` now finds the race on the handle.

Stated and not changed:
- The cut window before the write starts (after `admitted PENDING`, before the engine's first statement) writes
  nothing, so it heals: the refund's BEEF carries the JOIN and the engine lands a carried predecessor first (D17).
- A task the platform itself cuts (its `wait_until` budget after a cancel) still cuts the write; the deferred job put
  at rest when the request went is that case's replay, the job's run finding the JOIN unapplied and re-applying it
  whole while its coin is unspent. If a successor's admission removes the coin before the job runs, the half-write

- The ungated arms and the deferred job's own run (`WorkBudget::Resumed`) still await their write in the invocation

### 4a. The fold of the lens (FIX-936-FOLD, bsv-low `docs/audit/FIX-936-lens-2026-10-27.md`, NOT SOUND)

The lens found the paragraph above wrong about the platform: a cancelled request's future is never DROPPED on
wasm32 (the fetch export is a `future_to_promise` task, dropped only when it completes); it is never polled again
(s1) or resumed by the task's own wake (s2). So `Handle::drop` never fired, and the cover, the `RequestGone`
after-write, its line and its counter never ran. The fold:
- the write's own task runs `finish_past_deadline` on EVERY gated write, whether or not the request waits, named by
  the cause it reads at the write's end: `past-deadline` (the request marked the handle at its deadline),
  `request-gone` (the request's `AbortSignal` fired during the write), else `in-request` (the request runs its own
  copy beside it; the counters both share are counted by the request alone). Every line names the cause (LOW-2).
- the cover (`ef_deferred::defer_request_gone`) starts from the request's `AbortSignal` (`Request.signal`, read in
  `owned_write::RequestSignal::of`; `compatibility_flags = ["enable_request_signal"]` in `wrangler.toml` and both
  renders of `wrangler.low.toml`, the flag has no default date), never from a Drop: an uncancelled write puts
  nothing at rest. There is no `Drop` on the handle and the task never waits on the request (LOW-1 gone).
- pins: `owned_write::tests::fix936_g` (the lens's s1 and s2: the abort mid-write starts the cover, the write
  finishes whole, the task runs the guard, S2 and the counter and ends; RED on 8cf04f54 in its API, `left:
  ["insert_output", "output_admitted_by_topic"]`), `fix936_c` (rewritten: the base's cut is a request never polled
  again, not dropped), `fix936_d` (the cover runs once, only while the task runs), `fix936_e` (a waiting request
  takes the output and the task still guards), `fix936_f` (past the deadline, `past-deadline`), `fix936::fix936_b`
  (rewritten: the signal, the cover, the task's after-write, no Drop), `fix936_h` (one cause word on every line),
  `fix936_i` (the flag in every render). `fix838f_m1` and `fix838_the_gated_arm_races_its_write_and_hands_it_on`
  rewritten: past the deadline the request marks the handle and spawns no second after-write.
- the cost: on every gated write in the request, the task's after-write is a second copy of the request's guard (one
  `open_eviction` read, and the refused memo read when the door's readmission faulted), the notes flush, and on a
  write that is not durable a second S2 enqueue (a duplicate replay, dedup-safe), plus one log line. A cancel during
  the write costs #838's job at rest (its R2 or D1 put, its row, one delayed queue send) and one counter write.

| client shape | `wrangler dev --local` | raw `workerd serve` |

| (b) `http.request`, `req.destroy()` | not delivered | not delivered |
