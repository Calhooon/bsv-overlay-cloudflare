## Captain's ruling

A lost pf head CAS is `Contest`, terminal for these bytes. A client must re-plan
against the new head. `NotNow` is reserved for a predecessor not yet landed or
an unreadable verdict. It never means retry the losing head-spend bytes.

## Implementation status and the compatibility decision

This is a local candidate, not a release and not a completed PR. Names remain
proposals for the keeper; version 0.1.4 is untouched.

The atomic path uses one unit across all topics, managers, services, route
staging and applied rows. Its undo, stale-coin read-back and H2 write are gone.
Only an unanswered atomic commit enters its invocation's `not_landed` memory.
`NetworkAccepted` still selects the existing walk policy before staging; it
never bypasses admission guards or the unit's commit.

The repository's CLAUDE.md section "A faulted submit leaves one head" requires
its existing fault behavior for storage implementations which have not opted
into atomic admission. Revision 2 also explicitly requires unchanged
interleaving for those backends. The draft preserves that behavior in
`src/engine/legacy_admission.rs`, used only when `is_atomic()` is false. It
retains the legacy undo and H2 operations. Staged lookup services and route
staging are refused on that path before it judges or writes. This is a stated
exception to the brief's global removal of undo, not a claim that removal is
complete. The keeper must resolve that conflict before this can be called done.
A question was sent during the work; no ruling has been received yet.

The first attempt added a dry judgement before each real judgement. The broad
GASP harness caught the doubled calls. The final candidate instead stages the
normal judgement once. `restart_topic` replaces only that manager's uncommitted
writes/records when a carried predecessor lands and the engine re-judges the
topic. Guards of unaffected topics keep their identifiers. `end_topic` ends
that manager's scope before the engine and services stage. All 127 existing
GASP integration pins pass with this arrangement and the compatibility path.

## Public contract in this candidate

All names below are proposed to the keeper. The types are re-exported from
`storage.rs`; implementation details live in `storage/admission.rs`.

```rust
pub type GuardId = usize;
/// Proposed memory-only, typed record address.
#[derive(Hash, PartialEq, Eq)]
pub struct RecordKey {
    pub type_id: TypeId,
    pub key: String,
}
/// Proposed backend write with the bytes held by its binds, before copying to JS.
pub struct StagedWrite {
    pub write: Box<dyn Any>,
    pub bytes: u64,
}
impl StagedWrite {
    pub fn new<T: 'static>(write: T, bytes: u64) -> Self {
        Self {
            write: Box::new(write),
            bytes,
        }
    }
}
/// Proposed durable app-layer event. Never sent while staging.
#[derive(Debug, Clone, PartialEq, Eq, serde::Serialize, serde::Deserialize)]
pub struct OutboxEvent {
    pub event_type: String,
    pub txid: String,
    pub envelope: Vec<u8>,
}
/// Proposed commit precondition. The backend evaluates it before its own writes.
#[derive(Clone)]
pub enum Guard {
    OutputHeldUnspent {
        txid: String,
        output_index: u32,
        topic: String,
    },
    Backend {
        check: std::rc::Rc<dyn Any>,
        owner: String,
        bytes: u64,
    },
}
/// Proposed guard verdict. A lost head race is terminal for these bytes.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum PreconditionVerdict {
    Replay,
    Contest { kind: String, reason: String },
    NotNow { reason: String },
}
/// Proposed successful decision. A journal is not landed until closed.
#[derive(Debug, Clone, PartialEq, Eq)]
pub enum Committed {
    Batch,
    Journaled { journal: String },
}
/// Proposed four commit errors. Only Unanswered permits a late landing.
#[derive(Debug, thiserror::Error)]
pub enum CommitError {
    #[error("admission guard {guard} lost: {verdict:?}")]
    Precondition {
        guard: GuardId,
        verdict: PreconditionVerdict,
    },
    #[error("admission already applied")]
    Dedup,
    #[error("admission commit unanswered")]
    Unanswered,
    #[error("{0}")]
    Storage(#[from] StorageError),
}
```

```rust
#[async_trait(?Send)]
pub trait AdmissionUnit {
    fn is_atomic(&self) -> bool;
    fn insert_output(&mut self, output: &Output);
    fn mark_spent(&mut self, txid: &str, output_index: u32, topic: &str);
    fn delete_output(&mut self, txid: &str, output_index: u32, topic: &str);
    fn update_consumed_by(&mut self, txid: &str, output_index: u32, topic: &str, by: &[Outpoint]);
    fn record_applied(&mut self, tx: &AppliedTransaction);
    fn require(&mut self, guard: Guard) -> GuardId;
    /// Retained checks allow the engine to ask the owner after a failed commit.
    fn guards(&self) -> Vec<(GuardId, Guard)>;
    /// Replace a topic manager's uncommitted staging on a fresh judgement.
    fn restart_topic(&mut self, topic: &str);
    fn end_topic(&mut self);
    fn stage(&mut self, write: StagedWrite);
    fn emit(&mut self, event: OutboxEvent);
    /// `bytes` includes heap allocations owned by the record. Any alone cannot
    /// measure them; size_of_val measures only the header of a Vec or String.
    fn put_record(&mut self, key: RecordKey, value: Box<dyn Any>, bytes: u64);
    fn record(&self, key: &RecordKey) -> Option<&dyn Any>;
    async fn find_output(
        &self,
        txid: &str,
        output_index: u32,
        topic: Option<&str>,
    ) -> Result<Option<Output>, StorageError>;
    async fn guard_holds(&self, guard: GuardId) -> Result<bool, StorageError>;
    /// Sum of bind bytes and their copies, records and envelopes. Each BEEF
    /// is held once by txid, irrespective of the number of admitted outputs.
    fn charge(&self) -> u64;
    /// Remaining memory after the walk. Cross it through the journal, never refusal.
    fn set_memory_allowance(&mut self, bytes: u64);
    async fn commit(self: Box<Self>, bound: Option<&CallBound>) -> Result<Committed, CommitError>;
}
```

`CallBound` is public so backends can use its existing `call(future)` and
`is_due()` operations. `Committed::Journaled` records a durable decision; a
pending journal is not landed. The engine attempts its drain before answering,
and a replay drains before answering dedup. `MutationReport` distinguishes
`refused`, `unanswered`, `journaled`, and `after_commit_faults`, and reports
`admission_bytes` and the combined `memory_bytes`. `SubmitStage` receives the
actual `subject_txid` and `judged_topics`, including on carried predecessors.

The record byte count is explicit because `Any` cannot measure owned heap
allocations. Backend guards use `Rc<dyn Any>` so the check survives consumption
of the unit and the engine can ask its owner exactly once after a loss. The
context uses `RefCell` to retain the manager's shared-reference calling
convention. These three signature choices, and topic-scoped staging, need the
keeper's API review.

The compatibility unit reports non-atomic. Native MemoryStorage holds its
admission tables under locks, evaluates dedup and guards before publishing,
and applies a private transaction image only after every statement succeeds.
It holds one BEEF per txid. Its configurable statement/memory seams can force
a journal; they are not proposed D1 production bounds. Its journal's cursor
and each chunk advance together, including non-idempotent index increments.
Outbox sends that fail retain their rows and increment attempts.

## Following PRs

PR2 is Zanaadu's D1 unit and the guard/outbox/journal tables, its nine lookup
services' stage hooks, the writing managers' guarded writes and typed records,
route ledger staging, atomic readmit, typed door mapping, hosted rollback/error
pins and the measured budget. LOW's separate D1 backend also needs its unit.
Guard loss maps to terminal contest for those bytes; predecessor absence or an
unreadable verdict maps to NotNow. Outbox envelopes and lookup records must be
checked against the actual services, including first-admit emission.

PR3 is durable journal replay and outbox drain on boot and recovery, including
cursor arbitration, retry attempts, lag reporting and idempotent consumption.
The native model already provides replay/drain seams so those contracts can be
tested before platform integration. No production cron, boot drain, migration,
D1 backend or publication is part of this worktree.
