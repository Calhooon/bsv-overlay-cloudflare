# FIX-986 from-scratch lens (overlay PR 242, bsv-low #986)

**Verdict: NOT CLEAN** — 1 HIGH, 1 LOW, 1 NIT, 5 NOTE.

PR 242 = `lane/FIX-986` (475eb38a) on main 8f79b2b1. Reviewed from scratch: the
diff, the commit body, bsv-low #986's family D, and the touched code paths read
without the lane's reasoning. Deployed nothing, pressed no lever.

The contract (READ-986 family D, items 2(b)/3/5): a pre-signed refund broadcast
at its recovery height OUTSIDE the overlay's door is found by the discovery pass
(a pointer with NO verdict), proved by the confirmation pass (still none) and
skipped by the janitor's params backfill. D1's results view classifies it per
request from the spender's BEEF (`results::classify_from_columns`); the owed
actor's mirror holds no BEEF bytes, so it serves `unbound`/`unresolved` where D1
serves `payout refund claimable`. The fix makes the stored `pot_records.verdict`
group the ONE source both judges read, latched by every pass from the spender's
held BEEF through one classifier.

## What I verified sound (the money surfaces)

1. **The one classifier is the door's, extracted faithfully.**
   `spend_verdict::classify_pot_spend_tx`
   (`crates/overlay-discovery/src/pot/spend_verdict.rs:72`) is the door's inline
   logic lifted verbatim: conservation (`stake_a+stake_b == pot_sats`), the
   spend's OWN input for the recorded outpoint (index → #406 sighash, sequence →
   the refund gate), `classify_covenant`, then `settle_signers_for_spend`.
   `ls_pot::output_spent` now calls `classify_record_spend(record,&spending_tx)`
   (`lookup_service.rs:428`) over the record for the notification's own
   `(txid,output_index)` — byte-identical to the old door write. The door's
   admission answers are unchanged.

2. **Every new write is CAS-guarded and verdictTxid rides the pointer.**
   `verdict_cas_sql` (`d1_discovery.rs:2243`) and `mark_spent_sql(_,true)`
   (`:2068`) write `verdict/verdictTxid/settleSigners` only `WHERE spendingTxid =
   ?` (the spender the verdict was computed for), with `verdictTxid` bound to that
   same spender, in one statement. A moved pointer is a no-op; the group can never
   name a different spender than the live pointer it rode in with. The discovery
   pass's inline write (`proof_fetcher.rs:2453`) rides `mark_spent` under
   `spentConfirmed = 0` so a confirmed pointer is never clobbered. The chase
   (`:3328`) only latches when `!has_current_verdict`; the displacement (`:3524`)
   classifies from the proven bytes in hand, hash-checked `tx.id()==actual`, under
   the NEW pointer. All four writers call `pot_changes::note`, so the verdict row
   is a `pot` event the actor applies in Phase C (item 5).

3. **The classifier is hash-bound to the spender.**
   `classify_stored_spend` (`proof_fetcher.rs:2246`) selects the subject by
   `transaction_from_beef(beef,Some(spender),STORED_BEEF_LIMITS)` — the id is
   computed from the raw bytes, so a BEEF that does not carry `spender` yields
   `None` (pinned in `fix986_c`: a foreign spender / another spend's bytes classify
   nothing). A bare pot, an undecoded row or a missing funded value → `None`.

4. **D1 and the actor read the SAME verdict once latched, and the fix is
   monotone-safe.** The passes' `classify_covenant` is the identical function D1's
   tier-2 `classify_from_columns` (`results.rs:210`) calls, over the same column
   params, spender bytes and pot-input sequence — so the latched verdict equals
   what D1 derived from the BEEF. The differential pin `fix986_d`
   (`owed_actor/tests.rs:11660`) is real: the shipped D1 judge AND the real actor,
   the premise divergence (`payout refund claimable` vs `unbound`) reproduced, the
   latch replayed with the shipped `spent_unclassified_candidates_sql` +
   `classify_stored_spend` + `verdict_cas_sql`, then equal rows byte-for-byte and
   equal `rows_digest` on both the warm-apply (`pot` event) and a fresh bootstrap
   (seat B). The actor reads only tier-1 while D1 keeps its BEEF fallbacks, so the
   actor's served set is always a SUBSET of D1's: the fix can make the actor
   withhold, never over-serve (NOTE-4).

5. **The actor digest move is index-only (no re-bootstrap, item 5).** The new
   `CREATE INDEX IF NOT EXISTS idx_pot_spent_unclassified` is a plain index, so
   `is_plain_index` (`owed_actor.rs:786`) excludes it from `actor_shape`
   (`:707`): `schema_plan_kept` takes the index-only branch (rows, bootstrap and
   judgement kept, only indexes rebuilt). The regenerated `schema::DIGEST`
   (`b045…`) is confirmed by the passing pin
   `d2_actor_b_the_mirror_is_the_overlays_schema`.

6. **Eviction/retire/belt untouched; the migration-count `>=` gates hold.** The PR
   does not touch the eviction ledger, the retire pass or the belt. The
   owed-events (`OWED_EVENTS_MIGRATION_COUNT=473`) and owed-v2
   (`OWED_TRIGGERS_MIGRATION_COUNT=409`) gates are `>=` checks, satisfied by 474.

## Findings

### HIGH-1 — the PR fails `make ci`: the app-layer migration pin was not bumped
`crates/low-app-layer/tests/owed_derived_sqlite.rs:80,83`
(`owed893_migrations_preserve_the_shipped_prefix_and_pin_the_new_count`).

The PR appends overlay migration 474 (`idx_pot_spent_unclassified`) and bumps
`d1::OVERLAY_MIGRATION_COUNT` to 474 (`d1/mod.rs`), but does NOT update this
app-layer pin, which hardcodes `const COUNT: usize = 473` and
`const FINGERPRINT: u32 = 1_823_919_051`. The test imports the live
`bsv_overlay_cloudflare::d1::OVERLAY_MIGRATIONS`, so:
- `assert_eq!(OVERLAY_MIGRATIONS.len(), COUNT)` → `left: 474, right: 473`
- `assert_eq!(d1::OVERLAY_MIGRATION_COUNT, COUNT)` → 474 ≠ 473
- `assert_eq!(d1::migration_list_fingerprint(), FINGERPRINT)` → actual
  `2_769_134_649` ≠ `1_823_919_051`

**Run and confirmed RED** this lane: `cargo test -p low-app-layer --test
owed_derived_sqlite owed893_migrations…` fails at line 81 (`left: 474, right:
473`); with `COUNT` bumped to 474 it then fails at line 84 revealing the real
fingerprint `2_769_134_649` (which matches an independent FNV-1a recomputation of
the appended index string). `make ci` runs the workers workspace tests, so the PR
cannot land green as committed. The prefix fingerprints (`[..349]`, `[..409]`,
`[..469]`) and the drop-each-migration loop are unaffected (the new migration is
index 473, after 469).

**Fold:** in `owed893_migrations…` set `COUNT = 474` and `FINGERPRINT =
2_769_134_649`; re-run the test. (This is the sole break I found; the other
app-layer tests that import `OVERLAY_MIGRATIONS` only build the schema from the
list — the additive `IF NOT EXISTS` index is harmless to them — and the overlay
lib, discovery, owed_actor and fix986 pins are all green.)

### LOW-1 — the second-set candidate gate is narrower than D1's serving bar
`d1_discovery.rs:2151` (`spent_unclassified_candidates_sql`, `… AND spentConfirmed
= 1 …`) and the memory-store mirror (`overlay-discovery/src/pot/storage.rs`).

The backfill's second candidate set keys on `spentConfirmed = 1`, but D1 serves a
verdict whenever `is_confirmed_landing_with_proof` (`logic.rs:1956`) holds —
`spentConfirmed OR spender_proof_verified OR (seen AND final)`. A verdict-absent,
held-bytes row that D1 serves `claimable` via `spender_proof_verified` while
`spentConfirmed = 0` is NOT a candidate, so the actor keeps serving `unbound` (the
press withheld) where D1 shows it, until the confirmation pass sets
`spentConfirmed = 1` and latches. Normally that is a one-tick (confirmation-pass)
window — the chase re-verifies the proof and latches on the same tick — but if a
stored `proof_verified = 1` persists while the chase's fresh
`verified_proof_for_detailed` keeps returning None (a chaintracks reliability
edge), the withholding persists. (The `seen+final` arm is not reachable for a
discovery-found row: the discovery pass passes `spender_final = None`.)

No loss of funds and no over-serve (the user's own money, claimable once
confirmed), so this is below the HIGH, but it is a real incompleteness in the
PR's "one source both judges read" claim for the `proof_verified`-without-
`spentConfirmed` class.

**Fold:** since the reader gates SERVING on `confirmed_landing` (a verdict latched
on an unconfirmed row is never served), the second set can safely drop the
`spentConfirmed = 1` term (and its index predicate), or align the gate with
`is_confirmed_landing_with_proof`, so the proof_verified class is latched too.

### NIT-1 — the differential pin reconstructs the record instead of reading it back
`owed_actor/tests.rs:11582` (`janitor_latch`). The helper drives the shipped scan,
`classify_stored_spend` and `verdict_cas_sql`, but builds the `PotRecord` fed to
the classifier from the test params rather than mapping the scanned row through
`PotRow::into_record`. The reconstructed record equals the seeded row by
construction, so the pin is valid; a fully end-to-end latch would read the
candidate's own stored columns.

### NOTE-1 — a held-bytes row matching no mandated exit is a permanent candidate
`proof_fetcher.rs:3804`. A spent/confirmed/decoded-covenant row whose held spender
bytes match no mandated exit is never latched, stays in the partial index, is
re-sampled (`ORDER BY RANDOM()` reads the whole backlog each tick) and re-logs
`[params-backfill] … left unclassified` every tick. For a real covenant spend a
mandated exit always fires, so this is ~unreachable; both judges agree (both
`unbound`) so there is no money divergence; the cost is bounded (16/tick + the
backlog read) but a stuck row logs forever.

### NOTE-2 — `write_concluded` ('unresolved') vs the door's `write` (NULL) signers
`spend_verdict.rs:51,60`. The passes conclude `settle_signers = 'unresolved'` on a
no-pair spend (never retried by the #406 signers backfill), while the door writes
NULL (retried). `settle_signers_for_spend` is deterministic over the bytes and a
real signed spend verifies a pair, so the asymmetry only manifests on a no-pair
spend and is money-neutral (signers are a served attribution field, not a
claimability gate; a refund ignores them, and claimability uses `my_seat`).

### NOTE-3 — the budget tier does not cover the overlay's params backfill
The scheduled pass's statements moved (the new `find_spent_unclassified` scan +
per-candidate `get_beef` + `mark_verdict`, bounded at `PARAMS_BACKFILL_LIMIT`=16 a
tick plus a full-backlog `ORDER BY RANDOM()` read of the draining unclassified
set), but no rows-read ceiling in `tools/lane-499` or `tools/lane-834` measures
the overlay's params backfill — lane-834 measures only courier SUBREQUESTS, which
this PR does not change (the classifier reads `get_beef` from D1, not couriers).
I therefore did not run `make ci-d1-budget` (a heavy tmux/vultr tier, infeasible
in the foreground, and it would not measure the changed path). The new D1 cost is
bounded by reasoning (the unclassified backlog drains as rows are latched; beta's
was ~123 rows). If a bound is wanted, add a rows-read cell over
`/admin/complete-proofs`.

### NOTE-4 — the fix is monotone-safe (favorable)
The actor reads only tier-1 (the stored verdict); D1 reads tier-1 then its BEEF
fallbacks (tier-2/3). The actor's served set is therefore always a SUBSET of D1's:
the fix can only make the actor withhold a press, never over-serve a claimable the
chain does not back. The money-loss direction is closed.

### NOTE-5 — SQL `verdictTxid IS NOT spendingTxid` (case-sensitive) vs the reader's
`eq_ignore_ascii_case` (`results.rs:2093`, `has_current_verdict`
`proof_fetcher.rs:2258`). Harmless because every writer binds `verdictTxid` to the
same `spending_txid` string as the pointer (`verdict_cas_sql`, `mark_spent_sql`),
so the two are always byte-equal; the case distinction can only matter if a path
wrote them with differing case, which none does.
